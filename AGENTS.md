# Инструкции для ИИ-ассистента (Claude Code, Cursor, Copilot и т. п.)

Проект — фронтенд сайта доставки Frito (frito.kz). Сейчас статический, данные демо. Задача — подключить к существующему бэкенду и БД.
Перед работой прочитай: `docs/HANDOFF.md` (как устроено), `docs/BACKEND.md` (что заменить и черновик API), `docs/LAUNCH.md` (запуск), `docs/CHANGELOG.md` (что поменялось после передачи — переноси обновления из `updates/`).

## Как устроен код
- `*.dc.html` — шаблоны рантайма `support.js`: `<x-dc>` с `{{ }}`, `<sc-if value>`, `<sc-for list as>`, `<dc-import name="Компонент" kebab-пропсы>`; логика — `class Component extends DCLogic` с `state`, `setState`, `renderVals()`. В шаблоне только значения из `renderVals`, никаких вызовов функций и литералов массивов/объектов в атрибутах.
- Компоненты — `Frito*.dc.html` (без пробела). Страницы — строчные `*.dc.html`. Файлы `Frito *.dc.html` (с пробелом) — дизайн-макеты, на сайт не влияют.
- Общие стили и токены — `frito.css` (`:root`), компоненты `.f-*`; постраничные — `menu.css`, `checkout.css`, `status.css`, `account.css`, `vacancies.css`, `apply.css`, `info.css`.
- Глобальные объекты: `window.FritoContacts` (контакты — единственный источник), `window.FritoOrder`, `window.FritoStock`, `window.FritoAnalytics.track(event, params)`, `window.FritoI18n`.

## Правила
1. **Не редактировать `support.js`** — сгенерированный бандл.
2. **Цвета только токенами** из `frito.css` (`var(--primary)` и т. д.). Палитра бренда: белый, `#614BE2`, чёрный; красный/зелёный/жёлтый — только состояния. Новые цвета не вводить.
3. **Шрифты:** заголовки — `var(--font-display)`, текст — `var(--font)`. Цены — формат «4 090 ₸» с неразрывными пробелами (` `), используй существующую `fmt`.
4. **Новый UI — из существующих компонентов и классов `.f-*`.** Новый компонент или состояние — добавить в `Frito UI Kit.dc.html` (или `Frito Модалки.dc.html` для модалок).
5. **Тексты интерфейса** — на русском в шаблонах; для каждого нового текста добавить перевод в `frito-i18n-kk.js` (`"рус": "каз"`). Тексты из API должны приходить уже на нужном языке (`?lang=ru|kk`, язык — `localStorage.frito_lang`).
6. **Контакты** (телефон, почта, соцсети, бот) — только из `window.FritoContacts` в `frito.js`, не хардкодить.
7. **Аналитика:** при изменении воронки сохраняй вызовы `FritoAnalytics.track(...)` (список событий — `docs/AUDIT.md §5`); `purchase` — с настоящим номером заказа.
8. **SEO:** мета-блоки между `<!-- seo:start -->` и `<!-- seo:end -->` не править руками — генерирует `tools/seo.py` (после изменений меню, вакансий, контактов, адреса сайта — запусти его). Личные страницы (`account`, `checkout`, `status`) — `noindex`.
9. **Деньги и наличие считает сервер.** Клиентский расчёт — только предварительный показ. Номер заказа выдаёт сервер.
10. **Секреты не класть в клиент** (секретный ключ DaData, ключи эквайринга, токены ботов). Публичные ключи Mapbox/DaData — ограничить доменом.
11. **Проверяй в браузере** (`python3 -m http.server 8765` → `/menu.dc.html`): сценарий меню → корзина → оформление → оплата → статус → кабинет, на ширинах 375 и 1280+, на русском и казахском. Компоненты кэшируются — жёсткая перезагрузка.
12. **Корзина — по строкам, не по товарам.** Ключ строки — `lineKey(id, sel)` (товар + отсортированный набор опций), id товара из ключа — `pid(key)`. Один товар с разным составом — разные строки, одинаковый состав складывается. `cart`, `mods`, `extra`, `sels` — по ключу строки; каталог, стоп-лист, аналитика — по id товара. На сервер строки уходят по отдельности с `options`.
13. Мобильная и ПК-версии в одних файлах (переключение по ширине 1024px в `menu`, `checkout`); правя одну, проверь вторую.
