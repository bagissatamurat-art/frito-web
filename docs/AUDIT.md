## 2. Скорость — главная, живой сайт, первый визит

| Метрика | До оптимизации | После (WebP историй и иконки) |
|---|---|---|

| First Contentful Paint | ~1,5 с | ~1,3 с |
| Largest Contentful Paint | ~4,4 с | ~1,3 с* |
| Запросов при загрузке | 46 | 38 |
| Вес своих файлов первого экрана | ~820 КБ | ~185 КБ |

\* Замер в том же браузере: часть ресурсов уже была в кэше. На холодном мобильном соединении будет медленнее, а фото товаров с CDN (ниже) остаются главным риском для LCP при прокрутке и на узких экранах.

**Что уже исправлено:**
- истории `story-*.png` и иконка корзины `bag-frito.png` (304 КБ под иконку 34px) переведены в WebP: **−636 КБ**;
- картинки ниже первого экрана грузятся лениво (`data-src` + IntersectionObserver в `frito.js`);
- компоненты первого экрана подгружаются заранее через `<link rel="preload">`.

**Что нужно сделать на стороне бэкенда или CDN — самое важное:**
- фото товаров приходят **оригиналами 1600×900 по ~380 КБ**, а показываются шириной ~220px. 31 товар — это ~12 МБ при прокрутке меню. Нужны уменьшенные копии (480 и 960 px, WebP) и `srcset`. Одно это даст LCP < 2,5 с;
- сервер или CDN ближе к Казахстану, кэш и Brotli (LAUNCH §6).

## 3. Дизайн, UI Kit, компоненты

- **Цвета:** все цвета на сайте взяты из токенов `frito.css`. Цвета вне палитры заменены на токены: `primary-300`, `danger-50/100/ink`, `success-50`. Гайдлайн соблюдён: бренд — белый, фиолетовый и чёрный; цвета состояний — только для ошибок и успеха.
- **Компоненты в UI Kit:** все 30 компонентов есть в `Frito UI Kit.dc.html` или `Frito Модалки.dc.html` со всеми состояниями. Исключение — `FritoMethodModal`: он устарел и не используется.
- **Типографика:** заголовки и подзаголовки разделов набраны `--font-display` (Montserrat вместо Transforma), текст — Inter. Цены везде в формате «4 090 ₸».
- **Графика:** молнии и персонаж из исходников бренда (`assets/brand/`). Товары без фото получают заглушку с фирменным знаком.
- **Проверено на ширинах** 375 / 518 / 1280 / 1440 / 1600 / 1920 px.

## 4. Казахский язык

- Словарь — ~975 фраз и 11 правил. Пройдены все страницы: главная, оформление, заказ, кабинет, вакансии, анкета, франшиза, поставщики, помещения, доставка. Плюс все модалки.
- **Остаётся по-русски намеренно:**
  - названия блюд («Сеул бокс», «Делюкс бургер») и ресторанов — это бренд. В гайдлайне на казахском они латиницей; решение за маркетингом;
  - оферта и политика — нужен профессиональный юридический перевод.
- **Ограничение подхода:** перевод работает по словарю «рус → каз» в браузере. Любой текст, пришедший с сервера, останется русским, пока его нет в словаре. Поэтому API должен отдавать тексты на нужном языке (BACKEND §2.9).

## 5. Сквозные сценарии (демо)

| Сценарий | Результат |
|---|---|
| Меню → товар → способ получения → корзина → оформление → оплата → страница заказа | ✓ после исправления: оформление берёт настоящую корзину, оплата открывает созданный заказ |
| Товара нет в выбранном ресторане | ✓ скрыт в меню; при добавлении — окно с ресторанами, где он есть |
| Вход: код (неверный, блокировка, повтор) и Telegram (QR, телефон) | ✓ (демо) |
| Статусы: идёт, готов к выдаче, доставлен, оплата не прошла (отсчёт, другой способ, автоотмена), отменён (возврат) | ✓ |
| Заявки: франшиза, поставщики, помещения; анкета кандидата | ✓ (демо-отправка) |
| События аналитики: `view_item` → `add_to_cart` → `begin_checkout` → `add_payment_info` → `purchase`, `login`, `generate_lead`, `contact` | ✓ проверено с тестовым ID GTM: dataLayer и формат Метрики |
