# Frito — передача фронтенда разработчику

> Кому: разработчику, который объединяет этот фронт с бэкендом и БД Frito и выкладывает его на frito.kz.
> Связанные документы: [BACKEND.md](BACKEND.md) (данные и API), [LAUNCH.md](LAUNCH.md) (чек-лист запуска), [AUDIT.md](AUDIT.md) (результаты проверки).

## 1. Что это и в каком состоянии

Готов весь клиентский интерфейс:

- **Покупатель:** главная-меню, карточка товара с модификаторами, выбор доставки или самовывоза на карте, корзина, оформление, оплата (Kaspi или карта онлайн), статус заказа, личный кабинет (история, повтор, оценка, адреса, профиль), вход по коду через WhatsApp или через Telegram-бота.
- **Компания:** вакансии с анкетой, франшиза, поставщикам, предложить помещение.
- **Документы:** доставка и оплата, оферта, политика конфиденциальности, страница 404.
- **Общее:** казахский язык (переключатель в боковом меню), SEO (мета-теги, Schema.org, sitemap), аналитика (GTM, GA4, Яндекс.Метрика, Meta Pixel — нужны ID), фирменный UI Kit.

**Бэкенда нет.** Все данные зашиты в код или хранятся в `localStorage` браузера. Сервер имитируется: таймеры, случайные номера заказов, демо-коды. Полный список таких мест и чем их заменить — в [BACKEND.md](BACKEND.md).

## 2. Как устроен фронт

### 2.1 Рантайм `support.js` (dc-runtime)

Сайт работает на маленьком рантайме: `support.js` — это сгенерированный бандл, **не редактировать**. Он рендерит шаблоны `<x-dc>` из файлов `*.dc.html` на React (React подгружается рантаймом сам).

```html
<x-dc>
  <div class="{{ cls }}">{{ title }}
    <sc-if value="{{ isOpen }}">…</sc-if>                       <!-- условие -->
    <sc-for list="{{ items }}" as="it">{{ it.name }}</sc-for>     <!-- цикл -->
    <dc-import name="FritoStepper" qty="{{ qty }}" on-inc="{{ inc }}"></dc-import>  <!-- компонент -->
  </div>
</x-dc>
<script type="text/x-dc" data-dc-script data-props="{…}">
class Component extends DCLogic {
  state = { … };                 // как в React: this.setState(...)
  componentDidMount() { … }      // жизненный цикл React
  renderVals() { return { cls, title, isOpen, items, qty, inc }; }  // всё, что видно в шаблоне
}
</script>
```

Как это работает:

- **Логика.** Вся логика живёт в `renderVals()`, а шаблон только подставляет значения. Вызовы методов внутри `{{ }}` не поддерживаются.
- **Пропсы.** Пропсы компонента пишутся атрибутами в kebab-case (`on-inc`, `free-from`) и приходят в `this.props` в camelCase (`onInc`, `freeFrom`).
- **Массивы и объекты** нельзя писать литералом в атрибуте — передавайте их через `renderVals`.
- **Содержимое `<dc-import>`** приходит в компонент как `props.children` и выводится через `{{ slot }}`.
- **`<helmet>`** добавляет теги в `<head>`.
- **`ref="{{ myRef }}"`** работает (`React.createRef()`).
- **`data-props`, `hint-size`, `hint-placeholder-*`** — подсказки для дизайн-редактора, на сайт не влияют. `style-hover` и `style-active` — стили для состояний наведения и нажатия.
- **Общие данные.** Компоненты могут импортировать `frito-data.js` (ES-модуль) через `import('./frito-data.js')`.

**Варианты дальнейшей жизни фронта:**

| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Оставить как есть**, заменить демо-данные вызовами API (рекомендую для запуска) | Быстро; вёрстка, дизайн и логика уже проверены | Нет SSR. Яндекс индексирует хуже. Рантайм — внешний бандл |
| **Б. Перенести на React или Next.js** | SSR/SSG для SEO, привычный стек, TypeScript | Каждый компонент нужно переписать (шаблон → JSX). Логика `renderVals` и CSS переносятся почти 1:1 |

Для варианта Б всё переносимо без изменений: компоненты и их пропсы (описаны в `data-props` каждого файла), `frito.css` с токенами, классы `.f-*`, тексты, словарь казахского языка, `analytics.js` и `tools/seo.py` (часть с Schema.org).

### 2.3 Дизайн-система

- **Цвета** — только токены из `:root` в `frito.css`. По гайдлайну бренд — белый, фиолетовый `--primary #614BE2` и чёрный. Красный, зелёный и жёлтый допустимы только для состояний (ошибка, успех, «нет в наличии»). Цвета сервисов (Kaspi, WhatsApp, Telegram) — только на их кнопках.
- **Шрифты.** Заголовки — `--font-display`: Transforma по гайду. Шрифт платный, его нет, сейчас подставляется Montserrat. Подключите `@font-face` Transforma, и он применится везде. Текст набирается Inter.
- **Графика.** Молнии подключаются CSS-маской (`.f-g.f-g--bolt`, цвет задаёт `color`), персонаж — `.f-mascot` (`assets/brand/rooster-*.svg`). Фото без картинки получает автоматическую заглушку с фирменным знаком.
- **Цены** выводятся в формате «4 090 ₸» с неразрывными пробелами. Функция `fmt` есть в каждом компоненте, который показывает цены.

Всё это показано в `Frito UI Kit.dc.html`. Новые элементы стоит сначала добавлять в UI Kit.

## 4. План объединения (рекомендуемый порядок)

1. **Слой API.** Заведите один модуль, например `api.js` с функциями `getCatalog()`, `quoteDelivery()`, `createOrder()`… Компоненты вызывают только его. Контракты описаны в [BACKEND.md §3](BACKEND.md#3-черновик-api).
2. **Каталог.** Меню, модификаторы, цены, стоп-лист по ресторану, картинки (нужны уменьшенные копии, см. AUDIT). Убрать двойной каталог: `CATS` в `menu.dc.html` и в `frito-data.js`.
3. **Рестораны и доставка.** Список ресторанов с координатами и часами, полигоны зон, расчёт стоимости и времени на сервере.
4. **Авторизация.** Код через WhatsApp, Telegram-бот (deep-link + подтверждение номера), сессия или токен. Профиль и адреса — с сервера.
5. **Корзина → заказ → оплата.** Сервер пересчитывает цены и промокод. Оплата Kaspi (счёт) и картой (платёжная страница банка). Номер заказа выдаёт сервер.
6. **Статус заказа.** Реальные этапы с сервера: опрос раз в 10–15 с или WebSocket/SSE. Отмена, повторная оплата, автоотмена неоплаченного заказа на сервере.
7. **История, оценки, заявки, анкеты** — в БД, уведомления менеджерам.
8. **Запуск на frito.kz** по [LAUNCH.md](LAUNCH.md): домен, 301-редиректы со старого сайта, SEO, аналитика, ключи, реквизиты.

**Совет по порядку работы.** Двигайтесь сверху вниз по [BACKEND.md](BACKEND.md). Каждое место там помечено «сейчас → нужно». После каждого шага проходите сценарий «меню → корзина → оформление → оплата → статус → кабинет» в браузере.

## 5. Как проверять

- **Локально:** `python3 -m http.server 8765`, затем открыть `/menu.dc.html`. Компоненты кэшируются браузером: при правках делайте жёсткую перезагрузку.
- **Сценарии статуса** (демо): `status.dc.html?stage=accepted|paid|cooking|onway|done&mode=delivery|pickup&issue=paymentFailed|cancelled|delayed`.
- **Казахский:** в боковом меню «Рус | Қаз». Хранится в `localStorage.frito_lang`.
- **SEO:** после правок контактов, меню или вакансий запустите `python3 tools/seo.py`.
